FAQ and privacy

For a status on a key or dial, see Status screens and Troubleshooting. For changes by version, see the changelog.

Platform and requirements

Does it work on other operating systems?

No. Mac Sensors runs only on macOS. Its manifest declares macOS as the only platform, and the package carries native readers for Apple silicon (arm64) and Intel (x86_64) Mac computers only.

What are the exact requirements?

  • macOS 13.5 or later
  • Stream Deck app 7.1 or later, with the Node 24 runtime the app supplies
  • Tahoma Bold installed. It ships with macOS. The plugin checks for it by name on every system read. If it is missing, Sensor Reading keys, Sensor Dials and detail tiles show Tahoma needed until it is installed in Font Book; the next read clears the screen, and Check again checks at once.

These are declared floors, not versions that were all run. Measured: Apple silicon M5 Pro, macOS 27.0.1, Stream Deck app 7.5.0 on the Virtual Stream Deck. Physical Stream Deck key checks and Stream Deck + dial gestures are pending. See Hardware compatibility and Installation.

Sensor Reading goes on keys. Sensor Dial needs a deck with dials, such as Stream Deck + or Stream Deck + XL.

Is Mac Sensors affiliated with Apple or Elgato?

No. Mac Sensors is an independent project by Stephen Lawrensen, free and MIT licensed, with no ads. It is not affiliated with Apple or Elgato. Mac and macOS are trademarks of Apple Inc. Stream Deck is a trademark of Corsair Memory, Inc.

Do I need a separate sensor app?

No. The plugin reads macOS system counters and SMC readings itself, through the native reader in its package. It installs no separate monitoring app, privileged helper or daemon. There is also no data source to choose: each read covers the system counters and the SMC readings together. See Data sources.

Mac models and readings

Which Mac models and readings are supported?

Available readings depend on the Mac model and macOS version. A reading appears only when this Mac answers for it with a valid value.

On the measured Mac17,9 with an M5 Pro, the catalog has 38 SMC readings (temperatures, fans, power and related values) and 14 system readings: CPU usage, memory counters, swap, startup volume space, and network and storage transfer rates. Other models get a common table of typed SMC readings; the M5-specific table applies only to the measured model, and the plugin log notes that the model’s own catalog is not qualified. CPU and GPU clock speeds and GPU usage are not offered.

Hardware compatibility lists what was measured. Data sources explains what each reading means.

Does it run on Intel Mac computers or under Rosetta?

The package carries a separate x86_64 reader, and the plugin loads it whenever its Node runtime is x86_64. The x86_64 native reader in 1.0.1 is byte-identical to the one in 1.0.0. Hosted Intel CI runners (a virtual machine with an emulated SMC) loaded that exact file and read live system and SMC values for both 1.0.0 and the 1.0.1 release candidate. Physical Intel validation is in progress.

On Apple silicon the plugin loads its arm64 reader when the Stream Deck app’s Node runtime is arm64. Every Node runtime the Stream Deck app supplied on the measured M5 Pro is an arm64-only file, so it does not run under Rosetta. When Node runs as x86_64, the plugin loads the x86_64 reader and the support report’s translation field says translated. Outside the Stream Deck app, x86_64 Node 20, 22 and 24 running under Rosetta loaded that reader and read live values on the M5 Pro. The Stream Deck app itself has not been run under Rosetta, and Rosetta results are not Intel results. See Hardware compatibility.

Why is a reading missing?

The key shows Sensor missing / pick again when its saved reading is not in the current catalog on this Mac. This Mac may not offer that reading, its last read may have failed, or its value may have expired: a failed reading is removed at once, and no value is shown more than 15 seconds after it was acquired.

The saved selection, label and colors stay. When the same reading returns, the key shows it again. The plugin never substitutes the nearest name or list position. See Status screens.

If values are shown but do not seem to change, see Values do not seem to update.

Statistics

How are MIN, MAX and AVG calculated on a key?

macOS reports current values only, so Mac Sensors keeps its own statistics for every reading. MIN and MAX are the lowest and highest value accepted for the reading since the plugin last started reading sensors, and AVG is the arithmetic mean of those reads: one sample per read, including a read that repeats the last value, not weighted by time. The plugin starts reading sensors when a Sensor Reading key, Sensor Dial or detail tile becomes visible while reading is stopped, and stops 2 seconds after the last one disappears if none appears again, so changing to a page that has one, opening sensor details or pressing Back keeps them.

The statistics belong to the reading, so every key and detail tile that shows it shows the same numbers. They start over after a gap in that reading (a read where it is missing, withheld or failed, or the reading expiring 15 seconds after its last read), when its unit or type changes, and when the plugin stops reading sensors (2 seconds after the last one disappears) or restarts. After a sleep, CPU usage and the transfer rates skip one read, so theirs start over. Changing Read every keeps them. A key has no command that resets them. The full rules are under Value shown.

Alerts keep checking the current value whatever Value shown says.

How do dial session statistics differ?

A Sensor Dial keeps its own minimum, maximum and average for each reading, from the observations it accepted since the session started. Each new acquisition counts once, including one with an unchanged value; drawing the same acquisition again does not count. Each reading in a rotation keeps its own session, so turning away and back shows that reading’s numbers.

A session starts over when you reset it, when the reading goes missing, when its unit or type changes, or when a status screen replaces the readings. After a status screen, the first live frame shows stats reset: data gap. Sessions live in the plugin’s memory only.

A dial and a key showing the same reading can therefore show different numbers. A key’s statistics cover every read since the plugin started reading sensors. A dial counts only the reads made while it follows the reading (the reading on the dial, its rotation set or an overview’s list), from when it first followed it or was last reset, and any status screen ends its sessions. See Sensor Dial.

Sparklines

Why does a sparkline start empty and fill in?

The plugin keeps the last 36 samples of each graphed reading in memory and adds one per read while a Sensor Reading key (including the Back tile of a detail page), Sensor Dial or detail tile is visible. Every new acquisition is a sample, including one with an unchanged value. At the default Read every of 1 second, 36 samples take about 36 seconds; at 250 ms about 9 seconds; at 5 seconds about 3 minutes.

The line draws from the second sample and always spans the full graph width, so an early line is coarse and gains detail as samples arrive. Samples are spaced by count, not by time. CPU usage and transfer rates need two reads before they have a value; the second read runs about a quarter second after reading starts.

The line clears and starts again when:

  • Read every changes (Advanced, Connection).
  • A status screen replaces the readings, for example Reading sensors or No sensor data.
  • The reading goes missing or has no valid value, or its unit or type changes.
  • No Sensor Reading key, Sensor Dial or detail tile has been visible anywhere for 2 seconds, which stops reading. A page change, opening sensor details or pressing Back inside those 2 seconds keeps the line.
  • The plugin restarts.

Switching °F on or off does not clear it: samples are stored in the reading’s own unit.

Performance and resource use

How much CPU and memory does it use?

PERF.md in the product repository records each measurement with its build, host and harness; that repository requires access. The figures below are for the final 1.0.1 release candidate, run as a development copy in the Stream Deck app 7.5.0 on the M5 Pro (macOS 27.0.1), with 32 single-reading keys on an 8 by 4 Virtual Stream Deck. The harness was the development process observer, sampling the plugin process every 5 seconds in back-to-back runs against 1.0.0. CPU is the mean of two runs; RSS is the maximum of each run.

Read every Plugin CPU, one core Maximum RSS
1 second (default) 0.668% 88.2 and 89.3 MiB
250 ms 2.478% 95.9 and 94.6 MiB

A 24-hour observation of the final 1.0.1 release candidate, run as a development copy in the Stream Deck app with the 24-hour soak harness and 32 single-reading keys at 1 second, started at 76.94 MiB of RSS, closed at 82.08 MiB and peaked at 89.25 MiB. Its fitted slope was -0.011 MiB per 30 minutes, with 49 file descriptors at start and close.

Limits: one build’s CPU differed by 35% between two sessions in the same harness, other development work ran during the measurements, and dials, detail views and keys that mix system and SMC readings were not measured in the app. These are recorded results on one Mac, not a promise for another.

What does Read every change?

Read every (Advanced, Connection) sets how often the one shared read runs for every key and dial: 250 ms, 500 ms, 1 second (the default), 2 seconds or 5 seconds. Shorter intervals update sooner and use more processor time: in the table above, 250 ms used about 3.7 times the CPU of 1 second. An earlier 1.0.1 candidate in the same harness used 0.44% of one core at 2 seconds and 0.21% at 5 seconds.

Changing Read every clears sparkline history and keeps every MIN, MAX and AVG. A blank value means 1 second, and a stored value outside 250 ms to 5 seconds runs at the nearest limit.

Does adding keys add more sensor reads?

No. One shared read per interval serves every visible Sensor Reading key, Sensor Dial and detail tile, however many there are. Each extra key adds drawing work and messages to the Stream Deck app, not another read. When none of them is visible anywhere, the plugin makes no new reads, and 2 seconds later reading stops until one appears; Sensor Control keys do not keep it running. With nothing visible, the plugin process keeps running and keeps its connection to the Stream Deck app. In the measured show and hide cycles it made no reads, ticks or frames while hidden; those cycles ran on a build without the 2 second hold, and this is not a measurement of idle CPU. See When reading starts and stops.

A key can show up to four readings (Readings on this key), a dial can turn through a set of readings, and a key can open a detail page, so a deck can show more readings than it has keys. The measured bench above used 32 keys.

Can several keys show the same reading?

Yes. Each key keeps its own Label on the key, layout, theme, Text color, Decimals, °F, Value shown, Graph under the value and alert thresholds. They all use the same shared read, draw the same sparkline history for that reading and show the same MIN, MAX and AVG.

Alerts, thresholds and colors

Why is a key amber or red?

The current value reached a threshold set under Alerts in that key’s settings:

  • At or past Warn at, the whole key turns amber with dark text.
  • At or past Critical at, it turns red with white text.

By default a higher value is worse. Tick Alert when the value drops to or below these numbers where low is the problem, such as fan speed. Alerts check the current value in the reading’s own unit (°F when °F is on), even when Value shown names a statistic; for bytes and rates they check the source’s number and unit, which the key may show rescaled. On a key with several readings, only reading 1 is checked, and it recolors the whole key.

With Graph under the value set to Bar or Ring, muted amber and red zones mark the thresholds on the track whenever they are set, crossed or not. A zone is a landmark; the key’s color change is the alert.

On a dial the face keeps its theme: the bar takes the alert color, or in an overview the row’s value does. Once thresholds are set, the one-reading bar’s track also marks the warning and critical zones in muted amber and red. Dial thresholds apply only to readings in the unit that was on the dial when you last changed them. Alert colors are the same in every theme. To turn alerts off, clear Warn at and Critical at. How the colors look on a physical deck has not been checked yet. See Thresholds and alerts.

How do I reset a dial’s session statistics?

  • Legacy (the default): push the dial.
  • Elite: hold the push for at least half a second.
  • Custom: assign Reset session stats to Short push, Long push, Touch tap or Long touch.

A stats reset clears (under Controls) sets the scope: This reading only, The whole rotation set or Every dial, everywhere (use with care). A Sensor Control key set to Reset session stats sends the same command from any key, pedal or Multi Action, with its own A reset clears. The next accepted observation starts the new session. A Sensor Reading key has no reset: its MIN, MAX and AVG start over only as How are MIN, MAX and AVG calculated on a key? describes. See Dial controls and presets.

Themes

Why isn’t Default the same as Void?

Default is a link. A key or dial set to Default follows the shared theme under Advanced, Shared defaults, Theme, which every Mac Sensors key and dial set to Default uses. On a fresh install the shared theme is Void, so Default draws Void until you change it. Picking the Void chip instead keeps that key on Void when the shared theme changes.

In the theme strip the Default chip has a dashed frame and a link mark. The line above the chips names what is drawn: Default (shared: Void) follows the shared theme; Void (set on this key) is the key’s own pick.

If the plugin finds saved settings but no shared theme the first time an action appears, it starts the shared theme on Graphite instead of Void.

Why doesn’t a key follow my shared theme?

A theme picked on the key wins. Changing the shared theme affects only keys and dials set to Default. Pick the Default chip on that key to make it follow again, or choose Make shared to make the key’s theme the shared one and set the key back to Default. See Themes and colors.

Can I choose another font?

No. Faces use Tahoma Bold, and the panel shows Text font: Tahoma Bold. A font choice saved in a configuration document stays in the document and is not used.

Privacy

Is my data sent anywhere? Any telemetry?

No. The plugin makes no internet requests and has no telemetry or ads. It reads macOS interfaces and SMC readings on this Mac and draws the faces locally. Its only connection is the Stream Deck SDK’s WebSocket to the Stream Deck app at the loopback address 127.0.0.1. Settings are stored by the Stream Deck app, and logs stay on this Mac. The only web address in the settings panel is a link to this documentation.

What is in a support report?

Copy support report (Advanced, Support) builds a report on this Mac and copies it to the clipboard. Nothing is uploaded; it goes only where you paste it. It contains the plugin, Stream Deck app and macOS versions, the Node runtime version and architecture, the Mac model and chip, whether the plugin runs translated, the number of readings and any error codes from each source, the read interval and state, Stream Deck device models with hashed identifiers, and recent events.

It leaves out user names, serial numbers, hardware UUIDs, raw device identifiers and sensor values. Review a report before you share it. Event tracing is a development switch that is off unless set, and writes only to local logs. See Copy a support report.

Is the native reader signed? How do I verify what I installed?

The two native reader files, bin/hwmac-arm64.node and bin/hwmac-x86_64.node, are ad-hoc signed. An ad-hoc signature checks that a file is intact. It is not a Developer ID certificate, and the files are not notarized. Before it loads a reader, the plugin checks the file’s SHA-256 against the list in its own package and checks its architecture and protocol; a mismatch shows Bridge failed.

Each GitHub release publishes SHA256SUMS.txt beside the package and native-manifest.json; the releases require repository access. In the folder where you saved the package, run:

shasum -a 256 com.lawrensen.mac.streamDeckPlugin

The hash must match the package’s line in SHA256SUMS.txt. To check the installed readers, compare these hashes with the sha256 entries in the same release’s native-manifest.json, then inspect the signature:

cd ~/Library/Application\ Support/com.elgato.StreamDeck/Plugins/com.lawrensen.mac.sdPlugin/bin
shasum -a 256 hwmac-arm64.node hwmac-x86_64.node
codesign --verify --strict hwmac-arm64.node
codesign -dv --verbose=4 hwmac-arm64.node

The last command reports Signature=adhoc. Mac Sensors is not on the Elgato Marketplace yet. Elgato repackages Marketplace copies, so a GitHub hash does not apply to a Marketplace download. A checksum identifies bytes; it does not establish that a file is safe.

Hardware access

Does it need administrator access, a helper or a kernel extension?

No. Mac Sensors installs no privileged helper, launch daemon or kernel extension and needs no root or administrator password for normal reads. On the measured Mac, installing it showed no prompt beyond the Stream Deck app’s own install confirmation.

Can it change fan speeds or write SMC values?

No. The reader is read-only. Its SMC path accepts only read and key-metadata requests and rejects every other request code before it reaches the SMC; a test sends all 256 codes to confirm it. There is no fan control or other setter. Alerts change only what the plugin draws.

Setup and portability

Do keys survive restarts and sensor changes?

Yes. A key saves the identity of its measurement, not a list position or label. A system reading is saved by its counter name, such as CPU usage. An SMC reading is saved by the Mac model, its four SMC key bytes and a meaning revision. That identity does not depend on catalog order, labels or build numbers, so a new order after a restart cannot point a saved key at a different reading. A custom label changes only what the key shows.

If the saved reading is absent, the key shows Sensor missing / pick again and keeps its settings. When the same identity returns, the key shows it again.

Can I move settings to another Mac?

Yes, through configuration documents. Under Advanced, Configuration documents, Copy puts this key’s settings or the shared settings on the clipboard as JSON. On the other Mac, paste it into the same box and choose Replace this key’s settings or Replace shared settings. Replacing shared settings changes every Mac Sensors key and dial and asks for a second click. Fields this version does not know stay in the document.

System readings use the same identity on every Mac. An SMC reading’s identity includes the Mac model, so on a different model that reading shows Sensor missing until you pick one there. Nothing is rebound automatically.

What happens when my Mac sleeps?

After a sleep longer than 15 seconds, keys and dials can show No sensor data until the first read after waking returns, because every reading is older than its 15-second limit. After any sleep, CPU usage and transfer rates return one Read every interval later. This comes from the code and its software tests; real sleep and wake with a deck attached has not been checked yet. See Sleep and wake.

What do the two-line screens on my keys mean?

They name the condition the plugin can establish and the next step: for example Reading sensors before the first sample, Sensor missing for a saved reading this Mac does not offer now, Tahoma needed when the font is not installed, and Bridge failed when the native reader cannot load. The saved selection stays through every one of them, so there is no need to delete and rebuild a key. See Status screens for each screen and Troubleshooting for what to do.

How do updates arrive?

Open a newer .streamDeckPlugin package. The plugin has no update channel of its own and downloads nothing. Packages come from the project’s GitHub releases, which require repository access. Mac Sensors is not on the Elgato Marketplace yet. Opening a package with the same version as the installed one does nothing; see Opening the same version again does nothing.

Help and reports

Where do I report a bug or a security issue?

Report a bug as a public issue on the documentation repository. Name Mac Sensors and its version, the status on the key, and where you got the package; a reviewed support report helps.

Report a suspected vulnerability through the private security-report form, naming Mac Sensors and the affected version. Do not post exploit details, profile exports or private logs in a public issue. The first reply target for a security report is seven days.
